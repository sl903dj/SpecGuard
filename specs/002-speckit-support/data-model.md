# Data Model: Spec Kit 需求来源

本功能不新增报告文件格式。需求和任务继续使用现有实体。这里只增加选择来源时要用的字段。

## RequirementsSource

一次审核恰好一个来源。

| 字段 | 规则 |
| --- | --- |
| source | `openspec`、`speckit` 或 `auto`。`auto` 只在恰好一种来源有候选时解析成该来源 |
| selected | 解析后的来源。未解析成功时没有审核对象 |

## SpecKitFeature

| 字段 | 规则 |
| --- | --- |
| name | 功能目录名，形如 `002-speckit-support`。必须与目录名完全一致 |
| root | 仓库内的 `specs/<name>/` |
| spec_present | `spec.md` 是否存在。候选功能必须为真 |
| tasks_present | `tasks.md` 是否存在。缺失时记录工件缺失，不合成已完成任务 |

## 规格条目

映射到现有需求实体。

| 来源 | 标识 | 证据 |
| --- | --- | --- |
| 功能需求 | 规格中的 `FR-###` | 变更文件内容包含该标识才是直接证据 |
| 用户故事 | 故事标题 | 不能仅靠标题重叠成为直接证据 |
| 验收场景 | 故事下的 Given、When、Then | 随所属故事报告，单独重叠不是直接证据 |

## 任务项

映射到现有任务实体。

| 字段 | 规则 |
| --- | --- |
| marked_complete | 行首是 `- [x]` 或 `- [X]` |
| support | 变更中没有代码或测试支撑时为 `none`，并计入任务完整性缺口 |

## 状态

来源选择发生在构建和测试之前。

- 来源无法唯一确定：停止，不写报告。
- 来源确定但规格缺失或没有可核验条目：继续审核时，需求符合性为不可用。
- 项目不是 Java：代码检查不运行，限制说明写明不支持。
